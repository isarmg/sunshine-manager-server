# xscs 1.0.0

此版本将当前实现整理为 1.0.0 发布基线，正式标签为 `v1.0.0`，`main` 从一个初始提交开始。

项目、软件包、命令、服务、安装产物及移动端标识按统一四字母命名表更新；最后一位 `s` 表示服务端，`c` 表示客户端。当前项目名为 `xscs`。公共支撑分别为单体 Rust 包 `xcss`（仅 Linux AMD64 Server）与 `xcsc`（仅 Client）；Server Web 构建输入为单个 `@xcss/web` 包。

产品依赖固定到新的 1.0.0 基础库和提交。协议版本、数据库结构版本及第三方工具版本独立管理，不随软件发布版本重置。

升级前导出配置和业务数据，停止并卸载旧名称的服务，再按当前部署指南安装和重新配对。旧数据目录、系统服务及移动应用标识不会自动迁移。基础库项目通过依赖方式接入，无需单独安装后台服务。

参见[项目 README](../../README.md)与[统一命名表](../naming.md)。

## 内部版本从初始值开始

本次重建的软件发行号为 `1.0.0`。项目自定义的配置、持久状态、数据库 schema、API、通信协议、ABI 和发行清单均以 `v1` 或数值 `1` 作为初始标识；使用语义版本作为身份的配置采用 `1.0.0`。第三方依赖、外部软件 API 和字体上游版本遵循其实际版本要求。

服务端与客户端须成对安装本次 1.0.0 发行物。旧版配置或数据库不直接覆盖新目录；先导出数据并保留备份，再按平台部署文档重新安装和配对。

Sunshine 会话能力使用 `xscs-management/1`，业务任务使用 `xscs-task/1`。二者各自从版本 1 开始，通过不同名称保持独立的合同身份。客户端通过服务端维护的协议 crate 使用相同常量。

当前默认管理数据库名为 `xscs.sqlite3`，产品密文使用 `xscs:sgev1:` 前缀。协议名称会参与任务指纹计算，因此旧命名安装的数据库、执行记录和密文不得直接移入当前安装，也没有旧名前缀的兼容别名。先使用原兼容版本核对未确认操作并导出和归档数据，再按当前部署说明新建安装。

## 单体公共支撑与当前工作区更改

本项目的 Rust 公共能力只来自一个 `xcss` 包，内部模块已物理合并；整包仅允许 Linux x86_64 / AMD64 GNU。管理页面构建只安装一个 `@xcss/web` 包，原有认证、账户、界面、字体与构建工具改为包内子路径。Cargo 完整 revision、锁文件与唯一 Web tarball 的 SHA-512 integrity 同步核对。

本次提交同时纳入工作区已有的代码、界面和文档修改。部署入口与命令以当前[运维文档](../README.md)为准；历史拆分包的验证不代替最终源码的 CI、平台验收和发行资产核对。
