# Sunshine Manager Server 0.10.7

Sunshine instances now use encrypted, renewable authorization codes. Rotating a code revokes the current Client session and requires re-pairing, while cancelled unpaired instances can be permanently deleted.

Client pairing is aligned with Sunshine's native certificate identity, and the administrator Web follows the shared instance-list, detail, configuration, and log behavior with immediate language switching.

The runtime Foundation revision is now derived from the single exact revision in Cargo.lock, so release diagnostics cannot drift from the dependency graph. Current documentation and configuration no longer describe the removed direct-Sunshine, app/client, or cover-proxy architecture.
